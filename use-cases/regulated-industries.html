Scenario 1 PCI DSS · Drift

Keeping the cardholder-data environment segmented

Payments processor · PCI DSS Level 1 · dedicated CDE cluster and VPC · quarterly QSA reviews

The situation

During an incident an engineer added an ingress rule to let a monitoring tool outside the cardholder-data environment reach a database inside it. The rule was meant to be temporary. Months later the QSA found it while reviewing network diagrams, raising a segmentation finding that expanded the audit scope to the monitoring network.

Why it hurts

  • Segmentation failures expand PCI scope — more systems, more cost, more risk.
  • Temporary emergency changes became permanent by default.
  • Daily review of network rules was not realistic for the team.

How Netpin handles it

  1. Network driftSecurity groups and NetworkPolicies are compared with Terraform and manifests; the added rule is an out-of-band change, rated critical for a data-tier resource.
  2. PCI DSS controlsSecurity-group, public-access, encryption and logging controls map to PCI DSS 4.0 requirements and are re-evaluated continuously.
  3. Attribution and timelineWho added the rule, when, and every later state — the evidence a QSA asks for.
  4. AlertCritical security drift on the CDE alerts the security channel immediately.
  5. RevertA generated terraform apply -target removes the rule; Deploy Gate keeps future releases from reintroducing it.

What changes — and what to measure

Unauthorised CDE changesDetected within the hour for Terraform, 15 minutes for Kubernetes
PCI DSS weighted scoreTracked continuously
Segmentation exceptions at auditZero

Scenario 2 HIPAA · Encryption · Logging

Proving ePHI safeguards between audits

Digital health platform · HIPAA · BAAs with hospital customers · AWS (RDS, S3) + EKS

The situation

A hospital customer's security team asked for evidence that all storage holding patient data was encrypted, access-logged and not publicly accessible. One S3 bucket created by an analytics contractor had default encryption but no access logging; one RDS read replica had been created without backups. Neither had been noticed.

Why it hurts

  • HIPAA technical safeguards require ongoing assurance, not one-time checks.
  • Contractors and new services created resources outside the usual templates.
  • Customer trust — and contracts — depended on fast, complete answers.

How Netpin handles it

  1. Storage controlsS3 public-access block, TLS-only, encryption, versioning and logging; RDS encryption, public access, backups and Multi-AZ; KMS key rotation.
  2. Mapped to HIPAAResults map to Security Rule technical safeguards (access control, audit controls, integrity, transmission security).
  3. Unmanaged resourcesResources created outside Terraform appear as unmanaged or ClickOps drift, with who created them.
  4. Customer-ready summaryAudit readiness per framework in the Executive Brief, with evidence one click away.
  5. Stay compliantRegressions alert immediately; new resources are evaluated within hours.

What changes — and what to measure

Storage with full safeguardsTarget 100%
Time to answer a customer security reviewHours with evidence
Unmanaged data storesFound and owned

Scenario 3 Change management · Deploy Gate

Authorised change, evidenced automatically

Neobank · SOC 2 + PCI DSS · 300 production deployments a month · separation of duties required

The situation

Auditors sampled twenty-five production changes and asked for evidence of review, testing and approval for each. For pipeline deployments the evidence existed but was spread across GitHub, Jenkins and Jira. For four emergency changes made directly in the cluster there was none — resulting in a change-management exception.

Why it hurts

  • Evidence assembly took days for each audit sample.
  • Direct changes in production had no record at all.
  • Separation of duties could not be demonstrated consistently.

How Netpin handles it

Questions teams like yours ask

Is Netpin itself in scope for PCI or HIPAA?

Netpin uses read-only access and never stores secret values, cardholder data or patient data; it reads configuration, not application data. Discuss your specific scoping with your assessor.

Can we keep regulated environments separate?

Yes. Use a dedicated project for the CDE or ePHI environment with its own connections, members and thresholds.

Does Netpin store Terraform state or Kubernetes secrets?

No. State is read in memory for comparison and sensitive values are redacted; Kubernetes Secrets are reduced to names and keys.
