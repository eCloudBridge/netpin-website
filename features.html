New · What changed?

Drift Intelligence

Drift is any difference between what you declared and what is actually running. Netpin finds it continuously across Kubernetes, Helm, Argo CD and Terraform — then explains who changed it, why it matters, what it affects and exactly how to fix it.

  • Every source of truth — kubectl manifests, Helm release manifests, Argo CD sync status, approved baselines and a three-way Terraform code ↔ state ↔ cloud comparison
  • 14 drift types — out-of-band changes, unapplied code, stale state, ClickOps, unmanaged resources, runtime overrides, GitOps out-of-sync and more
  • Attribution — the person or tool behind each change, from Kubernetes field managers and AWS CloudTrail
  • Relational impact — affected services, shared ConfigMaps and Secrets, and internet-facing paths
  • Ready-to-run fixes — revert patches, adopt-into-code snippets and Terraform import blocks
  • Pre-flight risk — warns when a deployment would overwrite a live hotfix

How healthy are we?

Infrastructure Debt Index (IDI)

One 0–100 score, higher is healthier, that turns every finding, open drift and failed control into a number engineering and leadership both understand — and shows exactly where the points are lost.

  • Infrastructure health (40%) — failed releases, crash loops, missing probes and limits, open drift
  • Security posture (30%) — failed security controls, misconfigurations and security drift
  • Compliance (20%) — severity-weighted pass rate of the frameworks you choose
  • Operational excellence (10%) — CI/CD coverage, GitOps and Helm discipline
  • Fastest ways to raise the score — fixes ranked by the IDI points they recover
  • Forecast — 7, 14 and 30-day projections with "reaches warning in ~N days"

How it works

Each dimension costs weight × (100 − score) points, so Netpin can tell you "raising infrastructure health by 10 adds 4 IDI points" — and Deploy Gate can block production releases while the IDI is below your threshold.

Are we compliant?

Continuous Compliance

Automated controls check real settings on every connected AWS account, Kubernetes cluster and repository. Each result counts towards every framework requirement it satisfies — evidence is collected once and stays current.

  • 10 frameworks — CIS AWS Foundations, CIS Kubernetes, Pod Security Standards, NSA/CISA hardening, SOC 2, PCI DSS 4.0, HIPAA, ISO 27001:2022, NIST 800-53 and CIS Software Supply Chain
  • Honest coverage — every requirement is listed; manual-evidence items and missing data are shown, never counted as passes
  • Severity-weighted scores — a critical failure weighs 10×, high 5×, medium 3×, low 1×
  • Fix these first — controls ranked by weighted failures, with per-resource evidence and remediation
  • Exemptions built in — system namespaces and built-in roles never pollute your score

Is this release safe?

Deploy Gate

Every pipeline run is evaluated against your quality policies and the live state of the infrastructure it is about to change. The decision is reported back to your CI as a commit status.

  • Five pipeline dimensions — configuration, misconfiguration, failures, log analysis and steps
  • Real change risk — privileged or root containers, public exposure, removed limits, open drift, low IDI, incidents, rollbacks, failure history and dependency health
  • Quality profiles and gates — required, warned or ignored practices and metric thresholds, SonarQube-style
  • Approved, blocked or manual review — with every contributing factor and its evidence
  • Audited overrides — unblock with a written justification, recorded in audit logs
  • Native CI — GitHub Actions, GitLab CI and Jenkins webhooks

Multi-Cloud & Integrations

Connect a cloud account and Netpin discovers its managed Kubernetes clusters and connects to them automatically with short-lived credentials. Add Git and CI to light up drift, compliance and Deploy Gate.

  • AWS — EKS discovery and signed, short-lived EKS tokens from a least-privilege IAM identity
  • Google Cloud — GKE via a service account with roles/container.viewer
  • Azure — AKS via a service principal, including Entra ID (AAD) enabled clusters
  • DigitalOcean — DOKS with a scoped API token
  • Any Kubernetes — on-premises or other clouds via kubeconfig or token
  • Integrations — GitHub, GitLab, Bitbucket, Jenkins, GitHub Actions and Argo CD; Slack, PagerDuty and email
